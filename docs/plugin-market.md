# IPZSK 插件管理与调用归属

后台入口：https://api.ipzsk.com/admin → 插件市场与用量。

## 上架 SOP

1. 登记插件：标识、名称、GitHub owner/repo、npm 包名、收益归属编号、允许调用的模型。服务器生成永久 UUID。
2. 插件仓库独立构建，确认 `package.json` 的 name 与后台一致。运行 `npm pack`，将生成的 `.tgz` 附在 GitHub Release 上，tag 使用 `v1.2.3`，包内 version 使用 `1.2.3`。
3. 后台选择插件 → 版本管理 → 填 Release URL。有多个 `.tgz` 时填写附件名 → 导入为待审核。
4. 导入时验证 GitHub 仓库、附件大小、包名、版本、SHA-256。只读取 package.json，不安装或执行插件。代码、权限与客户端兼容性由管理员审核。
5. 确认上架后，登录用户可从 `GET /api/me/plugin-market` 读取已上架版本。每个插件返回最近一次确认上架的版本，支持重新上架旧版本回退目录；不自动证明本地数据可降级。
6. 下架某版本会退回该插件此前仍上架的版本；停用整个插件会隐藏全部版本，并拒绝该插件凭证的后续请求。

同一插件版本不得用不同内容覆盖。发布新内容时递增版本。GitHub 文件被删除会导致下载不可用，被替换会导致 SHA-256 不符；客户端安装器接入此目录时必须校验 SHA-256，不能仅信任 URL。

本次提供后台目录与审核接口。客户端市场 provider 更名、固定此信息源和按目录下载更新仍需单独接入；现有市场尚未改用该目录。后台接口返回的下载信息不会自动改变客户端已安装插件。

## 调用与凭证

`POST /api/me/desktop/bootstrap` 给主客户端和每个启用且具有运行配置的插件分别签发会话绑定凭证。插件配置包含 `plugin_id`、`credential`、`config`、`credential_paths`。凭证仅在主进程内存使用，不写入插件设置或磁盘。

凭证签发不证明插件已安装：无论客户端是否上报清单，凭插件凭证产生的归属只用于统计，永远不进入可支付分佣，见 COMMISSIONS.md“插件归属的可支付边界”。客户端可在请求体 `installed_packages` 上报已安装包名，服务端只为这些包签发凭证；不上报的旧客户端为兼容仍获得全部启用插件的凭证。

客户端必须使用插件自己的 `credential`，不能继续注入主客户端 token。新版 stable/beta 客户端已实现这一点；旧客户端的共享 token 请求仍显示为未归属。重新登录或重新 bootstrap 会轮换同一设备的凭证，注销登录会同时使对应插件凭证失效。其他设备不受影响。

新增插件可在后台设置运行时 ID、普通配置 JSON 和凭证注入路径；不要存入真实 API Key。客户端仅对已单独安装的包注入配置。无需模型权限的插件可以不配置运行时或模型。

网关根据已认证的 token 数据库绑定写入 `requests.plugin_id`，忽略客户端自行填写的插件标签；同时保存 `plugin_publisher_ref` 的当时值。插件 token 限制允许模型、禁止账户管理接口，并隔离媒体任务归属。不要把这种归属记录理解为防作弊分佣系统：本地用户仍然控制客户端，真正付款前需另行确定分佣和反作弊规则。

## 用量与分佣基础

- 保留每次请求 ID、用户、模型、插件 ID、收益归属快照、状态、输入/输出/总 token。
- 未提供 token 的上游请求保持 NULL，汇总显示未知笔数，绝不伪造 0 token。
- 生图同时关联任务状态；上游返回已确认费用时更新同一条请求，轮询和重复幂等请求不会重复累计。
- `cost_cny` 是上游成本，`request_billing.charged_cny` 是用户已实际扣款，两者分开展示。未知费用保持 NULL。
- `GET /admin/api/plugin-usage?from=YYYY-MM-DD&to=YYYY-MM-DD&plugin_id=UUID` 按北京时间请求发生日聚合，最多366天跨度。可导出汇总 CSV。
- 调用记录接口和逐笔 CSV 支持 plugin_id 筛选，含插件 ID 与收益归属快照。
- 历史共享 token 请求不猜测归属。本功能不自动计算佣金比例、创建分佣账单或打款；成本和晚到的账单可更新，未来结算需单独做周期快照与锁账。

## 验证

75 项后台测试（含隔离 PostgreSQL 审核、权限、凭证和统计测试）、stable 20 项与 beta 8 项相关测试、两版类型检查、stable 构建、真实登录→文字模型→插件生图联调。界面使用隔离数据验证列表、版本审核入口和费用展示；生产管理员登录未代用户操作。

## 三角色权限（2026-09-07）

- 超级管理员：`https://api.ipzsk.com/admin`。邀请插件开发者（“分佣与提现”页，见 COMMISSIONS.md）、停用开发者、插件审核与下架、所有者绑定、分成比例、平台用量及成本/收入、入账流水。
- 开发者：`https://www.ipzsk.com/developer`。复用普通用户登录；申请后由超级管理员批准。仅管理 owner_user_id 对应的插件，提交版本始终待审；待审版本可撤回，已上架版本只能申请下架。
- 普通用户：`https://www.ipzsk.com/account`。查看自己钱包、充值兑换、API 凭证和分页调用记录，可申请开发者资格。

开发者身份使用 `developer_profiles.user_id` 外键绑定业务账户。普通 API Token 不作为开发者后台登录凭证，管理员 Cookie 与用户 Cookie 不互通。所有开发者管理接口都按服务端登录身份检查 owner_user_id，用户参数不能指定或覆盖所有者、权限、分成或运行配置。

现有 operator/viewer 不具备开发者审批、插件审核、平台财务报表和入账流水权限。保留用户及号池运营权限；viewer 写操作仍被拒绝。超级管理员仍由已有 administrators.role 管理。

首次使用：用户登录开发者中心申请 → 超级管理员在“插件市场与用量”批准 → 开发者登记插件，或超级管理员把现有插件绑定到该开发者。既有生图插件没有根据 GitHub 昵称猜测用户账号，需管理员手动绑定到已批准的账号。

分成比例由管理员在插件“归属与分成”设置，可留空；0—100%，精确到0.01%。网关接受请求时记录 owner_user_id 和比例快照。开发者只看到自己在请求发生时拥有的调用汇总；后续插件转移不搬走历史收益。

开发者应计分成 = 每笔已实际扣款 × 请求时的分成比例（人民币8位小数，逐笔四舍五入后汇总）。未配置比例的已扣款请求单独计数。没有实际扣款就不形成已确认收入。系统不自动开启收费，也不执行佣金结算或打款。

管理员毛利仅包含“用户已扣款且上游成本已确认”的请求，计算为收入减上游成本，尚未扣除开发者分成；成本未知的请求不混入此数。退款、周期锁账与实际付款需要后续结算系统，当前应计分成尚不能作为不可变的已付款账单。

使用人数按成功的普通调用或已完成媒体任务去重，累计插件用户数跨模型去重；日期报表分插件/模型展示。开发者响应不返回消费者身份、聊天正文、凭证、上游成本或其他作者数据。
