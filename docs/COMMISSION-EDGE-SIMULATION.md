# 分佣边缘场景模拟审查

日期：2026-10-12。范围是本地代码、独立 `gateway_test` 数据库及模拟回执，没有真实扣费、转账或生产迁移。

## 本轮规则

有效付费 API 消费按 BD 20%、插件开发者 35% 独立计提。首次启用活动时记录开始时间和一年后的截止时间；暂停后恢复沿用原截止时间。赠送资金不分佣，退款和拒付按资金来源冲回。可信上游成本继续记录，用于平台毛利和账单核对，不影响两类分佣。

## 新增模拟

| 场景 | 验证结果 |
| --- | --- |
| 首次启用活动 | 固定保存 BD 2000 bps、开发者 3500 bps，截止时间等于开始时间加一年 |
| 冻结已提交的待转余额；执行器准备过程中并发冻结 | 不调用加额度，保持 pending；解冻后可继续 |
| 预留后收益被冲回为负 | 不发放无资金支持的余额；新收益抵偿后才继续 |
| 两个执行器同时处理同一转换 | 仅一次上游加额度、一次钱包入账，转入资金不分佣 |
| 极限转换 99999999.99999801 元，汇率 7、每美元 500000 quota | 使用整数精确上舍入得到 7142857142858 quota |
| 20 个冻结项目排在正常项目之前 | 后续轮次正常项目仍可入账，冻结项目保持暂停 |
| 消费日志超过一小时才到；旧版超时记为 released | 迟到消费可恢复，来源只分配一次 |
| estimated 先到、real 后到，期间汇率变化 | 成本按原销售账单汇率补记；100 元消费仍为 BD 20 元、开发者 35 元 |
| 同一回执被 8 次并发导入 | 仅一条成本审计、两条分佣流水，无重复发佣 |
| 负数、小数、超安全整数成本，用户或请求不匹配 | 不写入不可信成本；已确认的消费分佣保持不变 |
| 部分日志只有估算成本；重复日志 ID；分页未完整 | 标记账单异常，消费分佣不依赖该成本结果 |
| 真实成本明确为 0 | 100 元有效付费消费得到 BD 20 元、开发者 35 元 |
| 迟到成本同时改变销售 quota | 原销售额保留、成本不入账，标记 `lanehub_receipt_changed` 待核对 |
| 历史余额 100、已消费 20+10，再迁移剩余 70 | 两个历史请求隔离；新消费 70 元得到开发者 24.5 元 |
| 100 笔并发消费合计 100 元 | BD 合计 20 元、开发者 35 元；50 笔全额退款后为 10 元和 17.5 元；成本修正不改变分佣 |
| 16 组固定种子的混合余额、每组 7 档累计退款 | 用独立整数计算核对 20%／35% 金额和资金守恒，共 112 个退款检查点 |

## 复现入口

```sh
npm test
TEST_DB_HOST=127.0.0.1 TEST_DB_PORT=55439 npm run test:integration
TEST_DB_HOST=127.0.0.1 TEST_DB_PORT=55439 \
IPZSK_DESKTOP_BUILD=../ipzsk-dsh-desktop-next/official-desktop/.build/upstream \
node --test test/desktop-commission-chain.test.mjs
```

数据库端口必须指向独立的 `gateway_test`。数据库迁移版本为 31，重复迁移需要通过。

## 未决边界

- `historical_sources_review` 保留历史未决账目，须依据原始支付及消费来源人工核账。
- 已领取的 `applying` 是外部调用在途状态；响应不确定转 `review`，由管理员核对。
- 上游成本高于销售收入时，20%／35% 仍按有效付费消费计提，平台需要自行承担负毛利风险并监控定价。
- 本地模拟不能证明生产渠道单位配置、真实支付、真实退款或银行提现已经验收。
