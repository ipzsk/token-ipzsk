# 分佣边缘场景模拟审查

日期：2026-10-11。范围是本地代码、独立 `gateway_test` 数据库及模拟回执，没有真实扣费、转账或生产迁移。

## 本轮修复

| 问题 | 处理 |
| --- | --- |
| 待转余额创建后冻结／冲销，执行器仍向上游加额度 | 领取事务锁定收益账户，重新检查冻结、可用收益是否为负；暂停项轮转，多执行器仅一个能领取 |
| LaneHub 消费已同步，真实成本没有接入 | 读取 `cost_source=real` 的可信日志，验证完整性和用户／请求身份，自动保存实际成本并触发分佣；成本迟到继续扫描 |
| 未确认历史余额时误开启政策，后续无法迁移 | 开启前检查来源；迁移隔离未分配的历史消费，当前剩余余额只服务后续消费，已分配账目禁止重置 |

可信成本格式依据本地 LaneHub `2964937761ec446dfece89dfc0d656f23b300f18` 的 `model/log.go`、`relay/relay_util/upstream_cost.go` 和 `quota.go`。`estimated`、缺失或混合成本均不当实际成本入账。

## 新增模拟

| 场景 | 验证结果 |
| --- | --- |
| 冻结已提交的待转余额；执行器准备过程中并发冻结 | 不调用加额度，保持 pending；解冻后可继续 |
| 预留后收益被冲回为负 | 不发放无资金支持的余额；新收益抵偿后才继续 |
| 两个执行器同时处理同一转换 | 仅一次上游加额度、一次钱包入账，转入资金不分佣 |
| 极限转换 99999999.99999801 元，汇率 7、每美元 500000 quota | 使用整数精确上舍入得到 7142857142858 quota，修复浮点算法少 1 quota 的误差 |
| 20 个冻结项目排在正常项目之前 | 后续轮次正常项目仍可入账，冻结项目保持暂停 |
| 消费日志超过一小时才到；旧版超时记为 released | 未知保持待核对；迟到消费可恢复，来源只分配一次 |
| 旧超时账单让 Studio 生成记录显示为 0 点 | 迟到扣费恢复后按最终账单纠正展示点数；100 元显示 10000 点 |
| estimated 先到、real 后到，期间汇率变化 | 成本按原销售账单汇率补计；消费 100、成本 40 得 BD 12、作者 19.2 |
| 同一回执被 8 次并发导入 | 仅一条成本审计、两条分佣流水，无重复发佣 |
| 负数、小数、超安全整数成本，用户／请求不匹配 | 不产生实际成本或佣金 |
| 部分日志只有估算成本；重复日志 ID；分页未完整 | 不以部分成本或截断回执计佣 |
| 真实成本明确为 0 | 消费 100 得 BD 20、作者 32；未知值不走该规则 |
| 迟到成本同时改变销售 quota | 原销售额保留、成本不入账，标记 lanehub_receipt_changed 待核对 |
| 未知日志积压、每轮只准扫描一条 | 严格遵守预算，连续轮次处理不同请求 |
| 历史余额 100、已消费 20+10，再迁移剩余 70 | 两个历史请求隔离；新消费 70／成本 28 得作者 16.8；重复核对和旧成本更新不吃新余额 |
| 迁移输入超余额／有在途、缺账单、已有分配 | 拒绝并回滚，不留下半完成的来源迁移 |
| 100 笔并发消费合计 100、成本 40 | BD 合计 12、作者 19.2；50 笔全额退款后为 6／9.6；其余成本修正为亏损后两方均为 0，剩余来源 50 |
| 16 组固定种子的混合余额、每组 7 档累计退款 | 用独立整数计算核对 BD／作者金额和资金守恒，共 112 个退款检查点 |

既有用例继续覆盖观察期、月度提现、微额舍入、邀请奖励退回后重获资格、拒付与结算双连接竞争、退款后再次消费、账户隔离和上游响应丢失不重放。

## 复现入口

在网关仓库运行：

```sh
npm test
TEST_DB_HOST=127.0.0.1 TEST_DB_PORT=55439 npm run test:integration
TEST_DB_HOST=127.0.0.1 TEST_DB_PORT=55439 \
IPZSK_DESKTOP_BUILD=../ipzsk-dsh-desktop-next/official-desktop/.build/upstream \
node --test test/desktop-commission-chain.test.mjs
```

数据库端口必须指向独立的 `gateway_test`。桌面构建须先由 `official-desktop` 构建脚本生成。端到端模拟金额见 [客户端验收记录](COMMISSION-DESKTOP-SIMULATION.md)。

本地验证结果：单元／契约 149 项、PostgreSQL 集成 188 项、桌面完整链路 1 项全部通过；网站契约检查 0 drift，保留既有 31 条静态告警。数据库迁移版本更新为 30，重复迁移通过；其余测试中的版本快照同步更新。这些结果不表示生产已经部署或完成真实支付验收。

## 未决边界

- DeepSeek 文本目前没有实际费用回执适配，仍需可信账单确认；不能把 2.5 倍销售价反推值改称实际成本。
- `historical_sources_review` 保留历史未决收益，未自动补发；必须依据原始支付及消费来源人工核账。
- 已领取的 `applying` 是外部调用在途状态，后来冻结不能撤销已发出的调用；响应不确定转 review，人工核对后处理。
- 本地模拟不能证明生产渠道单位配置、真实支付、真实退款或银行提现已经验收。
